# Порядок работы над задачами

> Краткая выжимка процесса для исполнителя. Источник истины — `AGENTS.md` (разделы 4, 6).

## Одна фича — один коммит

Большие плановые задачи делаются строго по одной фиче за раз:

1. Реализовал фичу.
2. Проверки: `go build ./...`, `go vet ./...`, `go test ./...`, `gofmt -l .` (пусто),
   `npm run check` в `desktop/frontend`.
3. Dev-билд (`wails build` из `desktop/`).
4. Проверка заказчиком визуально/вживую.
5. Коммит (Conventional Commits, один коммит — одна логическая единица).
6. Только потом — следующая фича.

Несколько фич в одном коммите запрещены: так не возникает путаницы,
а любую фичу можно откатить, не затрагивая другие.

## Ветки (GitFlow)

- `main` — релизы, `develop` — интеграция. Прямые коммиты в них запрещены.
- `feature/<name>` от `develop` → merge в `develop` (коммит `merge: feature/<name> into develop`).
- Релизный тег `vX.Y.Z` — на `main`; фиксы — `1.0.x`, мажор — только по команде заказчика.
